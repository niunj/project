# vsgraysim 系统软件模块与功能说明

## 一、系统总览

vsgraysim 是一个多光谱装备仿真工作台，包含三大软件模块，构成"场景编辑 → 仿真数据生成 → 显控处理"的完整闭环：

```
导航页（启动入口）
  ├── 场景设计软件   — 地形编辑（生成/笔刷/水面/分析/工程存取）+ 多光谱场景部署与传感器配置
  ├── 仿真控制软件   — 时序子系统驱动 + RT 射线追踪回波/辐射数据生成
  └── 显控装配软件   — 链接仿真装备 → 按装备/平台类型装配对应显控界面
                      （雷达 / SAR / 红外等统一入口）
```

> 2026-09 架构调整：独立"地形编辑软件"移除，地形编辑能力（程序化生成、笔刷雕刻、
> 水面系统、地形分析、工程存取、rocky 地形包导出）整体并入场景设计软件；
> 原三个独立显控软件合并为统一"显控装配软件"。

仿真控制软件生成的数据通过 **GPU 句柄传递** 分发给显控软件，显控软件的处理/控制命令经控制通道反馈闭环。

## 二、基础公共模块

### gui/base/ — 基础 UI 库

四个文件，提供三个产品软件共用的界面基础设施：

| 组件 | 文件 | 职责 |
|------|------|------|
| **ThemeManager** | `ThemeManager.h/.cpp` | 统一暗色主题管理。`applyDarkTheme()` 设置 Fusion 风格 + 全局 QSS 样式表，消除三个产品窗口中重复的暗色主题定义。 |
| **WidgetFactory** | `WidgetFactory.h/.cpp` | 标准化控件工厂。提供 `createDoubleSpinBox`、`createSpinBox`、`createComboBox` 等静态方法，确保各产品窗口中相同用途的控件外观和行为一致。 |
| **DockBuilder** | `DockBuilder.h/.cpp` | Dock 面板构建辅助。`createDock()` 创建 QDockWidget + QScrollArea + QVBoxLayout 的标准结构；`addSection()` 在布局中添加 QGroupBox 分区。 |
| **BaseWindow** | `BaseWindow.h/.cpp` | 产品窗口基类（继承 QMainWindow）。封装公共菜单栏（文件/视图/帮助）、公共工具栏（返回导航页/重置相机）、公共状态栏（帧号/FPS）、标准化 Dock 创建方法 `createDock()`。提供三个虚扩展点供派生类覆写。 |

### gui/viewport3d/ — 3D 视口共享库

三层架构，三个产品软件共用同一套 3D 场景渲染引擎：

- **L0 - VsgQtWidget**：Vulkan 渲染宿主层，封装 vsg::Viewer 和 vsg::Camera 的 Qt 嵌入。
- **L1 - Viewport3DView + IViewportFeature**：特性组装框架层。`Viewport3DView` 是一个 QWidget 控件，内部包含 VsgQtWidget 和帧循环。通过 `applyConfig(ViewportConfig::fromPreset(...))` 按预设组装特性。每个特性（灯光、地形层、笔刷、视锥、轨迹等）实现 `IViewportFeature` 接口，通过 `FeatureRegistry` 静态注册。
- **L2 - Facade 门面层**：每个产品软件有独立的 Facade 类，封装与 3D 场景的业务交互：
  - `TerrainEditFacade` — 地形编辑的门面（并入场景设计软件，与 SceneDesignFacade 共存）
  - `SceneDesignFacade` — 场景设计的门面
  - `SimulationDisplayFacade` — 仿真预览的门面

两个视口预设对应不同软件的特性组合：
- `"scene_designer"` — 地面网格 + 地形层 + 灯光 + 轴向指示 + 相机限高 + 视锥 + 笔刷编辑 + 分析覆盖（含地形编辑）
- `"simulation_display"` — 地面网格 + 地形层 + 灯光 + 轴向指示 + 相机限高 + 视锥 + 场景预览 + 回放

共享组件库 `ViewportKit` 提供：默认灯光、模型加载、兜底地面网格、线段几何、传感器视锥顶点生成、实体变换矩阵等原语。

## 三、三大软件模块

> **地形编辑能力并入说明**：原独立"地形编辑软件"（Terrain Editor）已移除，
> 其全部能力迁入场景设计软件 —— 经 `TerrainEditFacade` 下发，对应 5 个地形 Dock
> （地形生成 / 地形笔刷 / 水面系统 / 地形分析 / 文件操作）、编辑菜单（撤销/重做）、
> 文件菜单的地形工程项、工具菜单的 rocky 地形包导出、状态栏的地形/水面信息。
> 笔刷编辑与实体摆放互斥（两者都占用视口左键，开启一方自动关闭另一方）；
> `TerrainStartDialog` 移除，地形工程选择由 `SceneStartDialog` 的
> "从地形模板新建"入口覆盖。

### 2. 仿真控制软件（Simulation Control）

**类**：`SimulationControlWindow`（继承 `ui::BaseWindow`）

**功能概述**：装载场景 → 初始化仿真管线 → 时序子系统驱动 → RT 射线追踪生成回波/辐射亮度 → GPU 句柄分发给各显控软件。

**菜单栏**：

| 菜单 | 项 |
|------|----|
| 文件 | 返回导航页、退出 |
| 仿真 | 打开场景、初始化 |
| 视图 | Dock 切换、重置相机 |
| 帮助 | 关于 |

**工具栏**：返回导航页、重置相机、录制数据、回放数据、清空日志、导出日志

**8 个分类 Dock（左侧 6 个标签化 + 右侧 1 个 + 底部 1 个）**：

| Dock | 位置 | 功能 |
|------|------|------|
| 场景装载 | 左侧 | 场景文件路径选择、装载并初始化按钮、场景摘要树（对象/传感器/环境）、高级传统配置路径折叠面板 |
| 播放控制 | 左侧 | 执行流程指示器（装载→初始化→播放）、播放/暂停/单步/停止按钮、倍速选择（0.5x/1x/2x/4x） |
| 显示选项 | 左侧 | RD 距离-多普勒图、距离剖面、多普勒剖面复选框 |
| 传感器监视 | 左侧 | 传感器 ID/类型/尺寸/脉冲表格 |
| 装备数据分发 | 左侧 | 数据服务在线/离线状态、雷达/SAR/红外三通道分发状态（帧数/开关机/显控在线/GPU 句柄） |
| 波段预览 | 左侧 | VIS/IR/RADAR/SAR 四波段图像缩略图 + 刷新按钮 |
| 性能监控 | 右侧 | FPS 曲线、平均帧耗时、仿真/真实时间比、三装备数据生成帧率（PerfMonitorPanel） |
| 装备状态与事件日志 | 底部 | 三装备开关机/帧率/流量/最近帧号表格 + 事件日志面板 |

**状态栏**：仿真状态（未初始化/运行中/已暂停/回放中）、仿真时间、帧号、FPS

**3D 视口预设**：`"simulation_display"` — 地面网格 + 地形层 + 视锥 + 场景预览 + 回放

**后端**：
- `Simulation` — 仿真主引擎
- `TimingBus` — 时序子系统（固定步长主循环）
- `EquipmentDataSource` — 装备数据源（发布 GPU 句柄到 SimDataBroker）
- `SimDataBroker` — 数据总线（GPU 句柄传递 + 控制通道）
- `EquipmentRegistry` — 装备注册表（供显控软件扫描链接）
- `FrameRecorder / FramePlayer` — 帧录制/回放

**核心流程**：
1. 装载场景 JSON → 展示摘要 + 3D 预览
2. 初始化仿真管线 → 构建 TimingBus + EquipmentDataSource
3. 播放 → TimingBus 驱动固定步长循环 → EquipmentDataSource 发布 GPU 句柄
4. 显控软件通过 SimDataBroker 订阅数据 → 本地处理 → 控制命令反馈

### 3. 显控装配软件（vsgraysim_control）

**类**：`ControlWorkbench`（`gui/display/`，装订式多装备协同显控工作台，继承 `QMainWindow`）

**功能概述**：直接在设备链路组合界面启动（无初始引导页），显示来自仿真进程的
在线设备与平台树（阵营色标记、在线/供电徽标）；选择设备 + 平台类型后自动绑定
`EquipmentSession`、建立数据链接，并按工作模式（`WorkModeRegistry`：搜索雷达/
制导雷达/SAR/红外等）在中央工作区装配对应显控面板。原三个独立显控软件
（雷达/SAR/红外）已并入本工作台，成为按装备类型装配的面板组。

**数据链**：设备数据按主题路由 `eq/<id>/radar|sar|ir|vis`，大帧经 SHM +
CUDA IPC 句柄零拷贝获取并注入本地 SimDataBroker；控制命令经 `eq/control`
主题路由（序列号 + 请求/回复确认），驱动仿真端真实操作（如断电停止帧生成）。

**雷达面板**（`RadarDisplayPanel`，原雷达显控软件并入）：
- MTI/MTD → CFAR → 航迹处理链（`CfarProcessor` / `MtiMtdProcessor` / `TrackManager`）
- PPI 显示（PpiDisplay）+ RD 距离-多普勒图
- 目标列表：目标 ID/距离/方位/多普勒/信噪比
- 制导雷达工作模式附加目标表 + 拦截弹状态 + 火控发射面板

**SAR 面板**（`ImageDisplayPanel`，原 SAR 显控软件并入）：
- ScrollableImageView 大幅面图像视图（缩放/平移/测量/ROI）
- 成像引擎（RD/CS）+ ATR 目标识别
- 处理接口：`lib/algo/sar/ISarProcessor`

**红外面板**（`ImageDisplayPanel`，原红外显控软件并入）：
- ScrollableImageView 热像图 + NUC/AGC/调色板映射
- 测温（十字/区域测温点、发射率/大气参数、NETD）+ 小目标检测
- 处理接口：`lib/algo/infrared/IIrProcessor`

## 四、软件间数据流

```
┌────────────────────────────────────┐
│            场景设计软件              │
│  地形编辑 (生成/笔刷/水面/分析/存取)  │
│            ↓ terrain_ref           │
│    实体 / 传感器 / 航迹部署          │
└─────────────────┬──────────────────┘
                  │ 场景 JSON
                  ▼
┌──────────────────────────────────────────────────────────┐
│                   仿真控制软件                             │
│  (场景装载 → 时序子系统驱动 → RT 射线追踪 → 数据生成)      │
│                                                          │
│      GPU 句柄传递 (雷达 / SAR / 红外 / vis 通道)           │
└─────────────────┬────────────────────────────────────────┘
                  │ eq/<id>/radar|sar|ir|vis + CUDA IPC 句柄
                  ▼
┌──────────────────────────────────────────────────────────┐
│             显控装配软件 (vsgraysim_control)               │
│    设备/平台树 → EquipmentSession 绑定 → 按装备类型装配    │
│    面板 (雷达 PPI / SAR 成像 / 红外测温, 本地处理与检测)    │
└─────────────────┬────────────────────────────────────────┘
                  │ 控制命令 (开关机/参数调整, 请求/回复)
                  └──→ 反馈回仿真控制软件
```

数据传递方式：
1. 仿真控制软件在 GPU 上生成回波/辐射亮度数据
2. 通过 `cudaIpcMemHandle`（IPC 句柄）将 GPU 内存共享给显控软件
3. 显控软件在本地 GPU 上执行信号处理/成像/检测
4. 控制命令通过 `SimDataBroker` 的控制通道反馈回仿真控制软件

## 五、系统架构要点

- **部署模式**：单进程部署（所有软件在同一个进程中运行），通过导航页启动/关闭各个窗口
- **架构模式**：三层视口架构（VsgQtWidget → Viewport3DView + Feature → Facade）
- **UI 架构**：BaseWindow 模板方法模式 + 多分类 Dock 设计
- **通信方式**：消息总线（SimDataBroker）发布/订阅，GPU 句柄零拷贝传递
- **时序控制**：TimingBus 固定步长主循环，可配置倍速
- **扩展性**：新的视口特性只需实现 IViewportFeature + 一行注册宏
