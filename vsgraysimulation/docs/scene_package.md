# 体素场景设计与仿真交换格式

本项目定义 `.vsimscene`（`vsgraysim-scene-package-v1`）作为正式场景设计器与仿真主控之间的交换包。它是本项目公开、带版本的格式，不是已有行业标准。旧 `.vtopic.json` / 体素检查点继续兼容。

## 本轮接入

- 原场景设计器右侧“体素地形与多波段属性”面板：导入 USD/USDA/USDC、VSG、OBJ、GLB、glTF、FBX 等模型；导入地图中声明的影像、高程工作区；抬升、降低、平整、平滑地形；按对象或局部体素中心 AABB 赋值。
- 导入采用后台准备、现有隔离资产编译进程、不可变快照、所有者线程统一提交。准备期间改变场景会拒绝过期结果。预算超限拒绝事务，不暗中降低碰撞或体素精度。
- 地形笔刷修改高度场和占用，重新构建既有统一几何与碰撞；显示、光学/红外/雷达使用同一发布版本。没有绕过断裂、刚体、占用、检查点系统。
- 光学参数为可见光/短波红外反射率；红外为温度 K 与分波段发射率；雷达为介电常数、介电模型编号、归一化粗糙度、σ⁰ dB、RCS 比例。RCS 比例不是给整个目标指定一个与视角和频率无关的固定 RCS。局部赋值保留范围外及未修改的参数，碎块沿用原材料索引。
- 整体赋值会清除旧局部覆盖，界面明确标示；局部赋值使用对象局部东/上/南米制坐标和体素中心判定，最多 256 个材料条目。参数为人工配置，不能自动视为实测或标定。
- 原“保存/另存为”、正式主控的打开场景、工作区场景卡片均识别场景包。现有显控在线平台、装备建链、租约、多进程 UI 与数据通道保持原流程。

## OpenUSD 目标发布

在体素专题的「体素地形与多波段属性」面板导入 USD 模型。当前导入静态多边形网格、
层级变换、面材质绑定、索引 UV 和 UsdPreviewSurface。基础色和法线可连接本地
UsdUVTexture，金属度、粗糙度、透明度使用标量，自发光使用颜色值。复杂材质可先烘焙
到 PreviewSurface，细分曲面可先三角化。尺度和向上轴从 USD Stage 读取。

目标沿用隔离资产编译进程和现有格距、占用、几何和碰撞流程。完成后台导入后，可在
「场景专题 → 发布体素场景包」保存 `.vsimscene`。发布在后台编码和写盘，清单在
资源写入后原子替换。已发布的目标包含体素占用及表面图集，重开时直接读取这些资源。
对比验证可以给 `tools/validate_formal_chain.py` 传入 `--topic` 指定带 USD 目标的专题。

### USD 目标编辑层

1. 在现有设计器打开体素场景专题，通过「场景专题 → 保存 USD 目标编辑层」导出
   `.usda`、`.usdc` 或 `.usd`。可用 OpenUSD 编辑器编辑，或在较强的子层覆盖参数。
2. 在原专题通过「场景专题 → 应用 USD 目标编辑层」应用组合后的图层。
   以对象 ID 匹配根目标及结构，并检查 WGS84 锚点、米制单位和 Y 向上约定。
3. 通过「发布体素场景包」交付仿真主控。设计器会把应用结果写入检查点，
   运行时直接读正式包，可独立部署。

编辑字段位于 `/Scene/Targets` 下，用 `vsgraysim:objectId` 标明对象。刚体位姿使用
USD Xform。光谱参数采用 `vsgraysim:sensor:*` 属性，雷达参数采用
`vsgraysim:radar:*` 属性。对象的 `cellChart` 保存网格定位、材料差异和体素索引段，
整体参数更新会传给继承该参数的格元，并保留局部赋值。导入会核对格距、尺寸和原点，
避免把同一份格元索引映射到其他网格。源模型、贴图及几何占用继续由原链路管理。
图层适用于暂停状态下的刚体位姿与多谱段材质编辑。地形雕刻、缩放、碎块和动画继续
使用各自的现有接口。

`openusd_voxel_publication` 测试层叠、局部材料继承、错误回滚、碰撞射线和传感器材质。
联调脚本可使用 `--usd-edits` 在现有设计器应用图层，并对比重开场景包后的 USD 导出。地球测试程序的
`--scene-topic-still <专题或场景包> <PNG>` 可在专题机位和冻结的场景时间截取 Vulkan 帧。

## 文件布局

```text
mission.vsimscene                  # 小型 UTF-8 JSON 清单，最后原子替换
mission.vsimscene.data/
  <sha256>.cborz                   # 不可变 CBOR + zlib 资源
```

移动时必须一起移动清单和同名 `.data` 目录。场景自身的占用、高度、影像图集、目标表面纹理/法线/金属粗糙度、局部多谱段属性均来自检查点资源；加载已保存的这些资产无需重新导入原模型、DEM。远景地球地图仍是外部部署依赖，不会将全球数据复制进每个场景包。

清单核心字段：

| 字段 | 内容 |
|---|---|
| `format` / `version` / `codec` | 格式名、主版本 1、`cbor-zlib`；不支持的版本拒绝加载 |
| `coordinates` / `units` | `east-up-south-metres`；长度 m、温度 K，角度遵循字段 `_deg` / `_rad` 后缀 |
| `topic` | 原有专题：地图、天空、云、相机、装备配置等；不含巨大内联检查点 |
| `checkpoint` | 固定步长、UTC、地理锚点、重力、时间、版本、断裂序号、日志、待执行事件等小型状态 |
| `objects` | 稳定 ID、角色、基础材料、物理参数、网格原点/尺寸/边长/基准位姿索引，以及状态/占用/材料资源哈希 |
| `earth_patches` | 共享的 DEM 高度、影像、海岸掩码与来源元数据资源表 |
| `surface_appearances` | 共享的目标表面细节、图集、法线和材质资源表 |
| `assets` | SHA-256 → 相对 URI、压缩字节数、解压字节数 |
| `residency` | 明确当前为有界权威检查点，远景沿用地图流式加载 |

哈希针对未压缩 CBOR 字节。加载校验长度、解压预算、哈希、引用和对象身份，再由既有引擎检查物理/材料/几何约束。资源路径不得以绝对路径、`..` 或符号链接逃出包目录。单资源至多 256 MiB，总解压至多 512 MiB，清单 8 MiB，最多 256 对象。已有物理工作区预算仍有效。

保存先写新增资源，再原子替换清单；不重写未变更的资源，不在保存时删除旧资源。遇到已存在但损坏的同哈希文件会拒绝保存并保留已提交清单。可删除的历史资源应由未来的独立归档/清理工具根据所有引用判断，不能在当前保存事务中直接清空。

仓库内地图可写为 `repo://config/earth/default.map.json`，由当前仓库或程序上级部署目录解析。台北数据仍使用 `VSGRAYSIM_TAIPEI_DATA_ROOT`，全球粗源使用 `VSGRAYSIM_EARTH_DATA_ROOT`。外部地图及其数据必须随部署准备，场景包不是全量地球数据容器。

## 精细地形与快速加载的边界

本轮把大型内联 JSON 拆成可索引、压缩、共享的独立二进制资源，并将源资产准备置于后台。清单查询不读取细节资源。当前运行时仍需将一个有界精细物理工作区完整解码并准备好，才一次提交；这不是完整 80 × 80 km 最细物理格网的按需分页。

80 × 80 km 台北区域默认仍由新数据地图提供远景；正式多谱段验收场景的精细权威地形工作区目前为 4 × 4 km、32 m 占用格，目标使用自己的原有体素格。显示细分不会改变碰撞破坏格距，也不能称为新增真实细节。地形笔刷只能在已准备的垂直网格 `(底面, 顶面]` 中编辑，达到底面或超过顶面会拒绝；当前面板为参数式范围编辑，不是连续鼠标雕刻笔刷。

### 四块地形页试验

在设计器选择「场景专题 → 发布分块体素场景包」，或在 `scene_package pack` / `benchmark`
末尾加 `--terrain-pages`。专题字段为 `"terrain_paging": "quad-v1"`。普通包继续可读。

目录 `terrain_pages` 把静态地形根的完整网格切成四个格元对齐的页，每页有自身的
压缩资源哈希、覆盖范围、DSM 采样、RGBA 像素和占用位图。相邻页共享同一条高程样本边，
装配时校验。像素使用原图集坐标，格元只归属一个页。破坏和笔刷修改随检查点发布，
未变化的页可复用其已有资源。无法按完整网格切页的地形对象继续使用原编码。

`VoxelScenePackage::terrainPagesAsync` 在后台按场景局部 XZ 范围读取并校验页资源。
可用 `scene_package read-terrain <包> <xmin> <zmin> <xmax> <zmax>` 检查实际读取的页和字节。
设计器、仿真主控与原显控的 Vulkan 视口打开分块包时，会沿用同一网格并按相机视域上传
与释放各页的顶点、法线、纹理坐标和索引。视域外邻页可提前在后台准备。相机突然跳转时，
当帧需要的地形页在绘制前就绪。精细地形沿用原图集、光照和空间坐标。
GPU 页统计记录几何缓冲的数据量，驱动内存池、共享图集和传感器加速结构另有开销。

物理与传感器继续从完整权威工作区取数，场景包后台仍须装配这部分数据。
后续可沿用 `TiledVoxelTerrain`，将刚体活动范围、历史测量与传感器视域接入运行时驻留，
同时保留相邻页和在途仿真依赖。

地球测试程序可用 `--scene-terrain-page-traverse <包> <输出目录>` 对比普通包与分页包。
每次以同一相机路线掠过页交界，记录原生 Vulkan、Bullet 接触、两路 GPU 光学/红外测距、
地形笔刷、破坏以及场景重开。渲染和完整周期分别采样，破坏更新时间单独列出。

## 画面目标

可将 DCS World 的大气、云、地形和座舱作为视觉参考，将 GTA 官方画面的地表细节、材质与场景构图作为参考；不能保证当前数据和预算达到同等整套观感。保持现有体素架构仍可改进抗锯齿、稳定曝光、PBR 材质、阴影、连续云密度采样和大气散射，体素占用不要求画面表现成粗立方体。

台北 Sentinel-2B 10 m 影像不是近地高清道路/建筑纹理，GLO-30 DSM 不是裸地 DTM；近地 AAA 级细节需要更精细的合法数据、建筑/道路几何、材质资产和美术调校。缺少来源的建筑高度/道路宽度必须标为推定。漂亮 RGB 图像也不能替代对红外或雷达散射的标定验证。

## 验证

`scene_package_authoring` 覆盖 SHA-256 独立已知向量、精确检查点往返、资源复用、迁移、启动列表、损坏资源拒绝、地形编辑、显示/碰撞/传感器几何一致性、材料重涂、预备资产导入与失败事务回滚。

实际三软件验证命令：

```sh
PYTHONPATH=build/scene-package-python python3 tools/validate_formal_chain.py \
  --package --output build/scene-package/formal
```

`--package` 下独立检查二进制资源的 Python 验证器需要 `cbor2`。实际产品加载不依赖 Python 或此模块。截图来自实际 Vulkan 窗口，不使用合成效果图。加载、渲染、完整仿真是不同指标，应分别测量；格式压缩率不能作为实时帧率结论。

## 2026-11-22 本机验收结果

- 6 项回归通过：统一地球场景、结构断裂、场景运行时、多装备 GPU 通道、正式专题链路、场景包编辑。
- 台北新数据实际设计器中执行地形降低、飞机局部温度 620 K/反射率/雷达参数赋值，保存 `.vsimscene`，退出后由第二个设计器进程重开并另存。完整检查点相等，含修改后的高度与体素属性。
- 实际仿真主控恢复该场景，原显控通过在线建链接收可见光、MWIR、LWIR、雷达 RD；源端与显控载荷完全一致，断电控制只停止所选装备，暂停保留最后产品。此轮为晴空陆地四装备验收，不代表海洋/云全天候多谱段已验收。
- 修复体素专题暂停时天空按墙钟继续推进的问题：天空日月跟随当前场景时间，原独立环境预览仍使用自己的时钟。两次设计器的天空累计时间均为 0 s，同机位同 UTC 实际 Vulkan PNG 逐字节相等。截图前等待环境资源稳定，不把加载期间的中间帧作为最终对照。
- 新增底面越界拒绝、去除已删除体素的失效断裂键、旧破坏孔洞保留、后台导入取消、损坏场景卡片跳过测试。

台北验收包的三次热缓存 CPU 测量中位数（NVMe 文件缓存已热；不含渲染、完整仿真步进）：

| 项目 | 测量 |
|---|---:|
| 同一检查点紧凑 JSON | 16.206 MB |
| 场景包实际引用资源 + 清单 | 6.993 MB，减少 56.85% |
| 清单大小 / 读取 | 10.54 KB / 0.133 ms |
| 新包完整解码（含解压、校验、恢复 JSON） | 75.36 ms |
| 同一状态紧凑 JSON 解码 | 50.56 ms |
| 解码后规范几何与物理世界准备 | 231.27 ms |
| 本次复用资源保存 | 65.13 ms |

优化前新包完整解码为 135.60 ms。减少独占资源的多余复制，并可选使用系统 OpenSSL 3 的 SHA-256 单次计算接口后降至上述结果；缺少 `libcrypto.so.3` 时回退到内置实现，文件哈希不变。`VSGRAYSIM_PORTABLE_SHA256=1` 可强制回退做对照，两种实现均测试已知向量。SHA-256 只是完整性校验，不是加密或发布者认证。

**不能据此声称完整加载全面快于热缓存 JSON。** 当前收益是包体积、轻量清单查询、不可变资源复用、后台源资产准备；规范几何/BVH/物理准备仍需要工作。下一步应把编译后的原生几何、加速结构缓存与按需驻留实现到现有体素机制中，而不是降低体素或碰撞精度。

本机产物：`build/scene-package/formal/report.json`、`build/scene-package/formal/designer.png`、`build/scene-package/formal/designer-reopened.png`、`build/scene-package/loading-optimized.json`、`build/scene-package-regression.log`。这些加载时长不是渲染帧耗时，也不是完整仿真性能。可复现格式测量：

```sh
build/scene_package benchmark build/scene-package/formal/reopened.vsimscene \
  build/scene-package/taipei-authored.vsimscene
```
