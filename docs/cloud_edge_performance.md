# 近云细节、带风重投影与海面尖点

本轮继续使用原单云对象及体素/断裂/刚体/碰撞/检查点链路。场景仍采用台北新 GLO-30 DSM 与 2024-02-14 Sentinel-2B，保留 `default.map.json` 的区域覆盖和全球回退。云是合成天气，不是该日期的实测云资料。

## 云的显示与光照

- 单云的随机种子、大小、密度和运动模型不变。CPU/GPU 点密度、分箱与完整云群扫描保持一致；凝结面以下的密度严格为零，据此收紧显示包围盒，并跳过云包围盒之间的空段。有云的区域继续细步积分。
- 贴近云边的视线步长从 16 m 改为 10 m，随距离过渡到原有中远景步长。循环容量相应增加，防止加密后过早截断。它是显示积分采样，不修改物理体素或碰撞精度。
- 每个云对象在 GPU 缓存 48³ 的归一化粗凝结体，仅供光照采样；单元带一格边界，144 个槽位组成 300×300×200 的 R32F 图集，约 68.7 MiB/视口。相机、位置、朝向、密度包络和日月方向变化不要求重烘焙。形状种子或归一化长宽比变化才更新相应云槽。
- 光照最近的日光采样使用完整连续密度，较远日光及天空光查询缓存。漫射天空同时采样天顶和朝向主光的斜天空，按透射率作 70/30 混合，再转换为有效光学深度。缓存是有误差的显示 LOD，不作为定量传感器输入。
- 缓存只在实际记录烘焙命令后生效；未准备好或失效的云槽使用直接密度计算。隐藏云停止烘焙。初始化、写后读及后续读写都有 Vulkan 屏障。云移动、成长和密度变化仍通过当前变换/包络参与查询，没有冻结一份旧世界坐标云。
- 半分辨率离屏云通道专门编译单云对象路径；独立稀疏体素云与直接绘制回退继续保留其通用路径。默认仍为半宽半高积分、原尺寸重建。

## 近景坐标与运动重建

近云原来先上传归一化 ECEF 眼点，再在 GPU 放大并与地球尺度原点相减。移动时的浮点量化误差会干扰微小云絮。现在在 CPU 双精度中先求云图表的相对眼点，再上传米尺度坐标；大气的原接口继续保留。

原先所有云共用一个平均风位移，而单云各自的漂移速度和成长速度不同。离屏积分现在标记主要贡献的云对象，重建从原始采样中选择透明度贡献较大的对象标签，避免线性插值混合对象编号。CPU 保存实际记录过的上一帧单云变换，在眼点相对坐标中生成每云仿射映射，包含漂移、抬升和缩放。标签缺失时使用既有回退，生命周期重置/映射失效时拒绝旧历史。

重建采用受限三次插值，对预乘 HDR、Alpha 和直通颜色范围同时约束，避免新增亮边。颜色变化也参与历史拒绝，使不透明但照明已变的云絮不再只因 Alpha 相同而继续沿用旧值。多层半透明云仍使用主要贡献对象及代表性深度，不是逐个体积采样点的精确历史追踪。

## 海面亮点、暗点

水面原来同时叠加未经过粗糙度过滤的日月小盘及 GGX 高光。水面现在通过一个粗糙高光项表现日月反射；水下斯涅尔窗口保留日月盘。像素法线变化参与粗糙度及环境反射的角度过滤，抑制过尖的亚像素高光。半程向量在光线与视线相反时使用有限的单位向量回退，GGX 分母改为避免相消的表达式。

波谱、水位、浮力、水线积分及碰撞几何未变。正常波光仍然存在，图像里的高亮/暗邻域差异不能全部称为错误点。

## 验证与复现

原始基线可执行文件为 `build/cloud-edge-perf/earth-before`；原航线来自该程序当前云密度实际选边，冻结为 `wind-before/route.json`。前后逐帧核对相机、UTC、仿真时间、源质量和眼点处凝结量。

```sh
build/gui/sim_earth_gui_tests --scene-cloud-object-wind-flight \
  build/cloud-edge-perf/wind-after build/cloud-edge-perf/wind-before/route.json
VSGRAYSIM_OCEAN_WEATHER_PASS=1 VSGRAYSIM_CLOUD_HALO_PASS=1 \
  build/gui/sim_earth_gui_tests --scene-ocean-capture build/cloud-edge-perf/ocean-after
VSGRAYSIM_OCEAN_WEATHER_PASS=1 VSGRAYSIM_OCEAN_SHIMMER_PASS=1 \
  build/gui/sim_earth_gui_tests --scene-ocean-capture build/cloud-edge-perf/shimmer-after
VSGRAYSIM_CLOUD_UPPER_EDGE=1 VSGRAYSIM_CLOUD_DENSE_FLIGHT=1 \
  build/gui/sim_earth_gui_tests --scene-cloud-object-wind-flight build/cloud-edge-perf/upper-after
python3 tools/compare_cloud_edge_perf.py
```

原航线 52 帧、640×360、8 m/s 风，包含接近、固定机位看风和穿越。其采样间隔为 0.4 s，大于历史复用上限 0.25 s，因此不能用它单独证明正常帧率下的时间重投影质量。补充 30 Hz 仿真时间连续采样，单独记录历史资格并输出原始帧；截图/编码使采集墙钟时间变长，这不是实时录屏帧率。

海洋使用同一舰船场景、960×540、五个白天/日落机位；额外三种 UTC 各 16 张小幅移机图像，在固定水面仿真时间下检查尖点。固定 ROI `[0.15W,0.65H]–[0.85W,0.92H]` 统计相对八邻域中位数的局部亮暗对比，以及未配准相邻帧的变化。它们是图像指标，不是错误像素真值；原始亮点可能是真实波光，未配准变化也包含视差和正常反射方向变化。

GPU 验证覆盖点密度、加速查询对照完整扫描、空段不跨过有云采样、光照缓存的有效性/回退/休眠云成长/移动复用、独立单云重投影、不透明光照变化拒绝、HDR 云边，以及退化高光向量和法线方差过滤。海面高度/法线/光学界面继续执行原 CPU/GPU 对照，另外执行传感器一致性回归。

各机位渲染提交及 GPU 等待统计写入 `build/cloud-edge-perf/comparison.json`。截图编码、加载和冷管线编译不进入稳定帧计时。本轮不重测完整仿真、浮力或毁伤更新，不能用渲染耗时替代它们；高分辨率、多显控和全天气量化辐射仍需各自验收。

诊断开关：`VSGRAYSIM_CLOUD_LIGHT_CACHE=0` 使用直接光照密度查询；`VSGRAYSIM_CLOUD_TEMPORAL=0` 使用既有直接绘制回退，它也绕过独立天空雾，不是仅修改一个历史权重的消融实验。

同相机、同UTC、相同规范云密度。640×360；计时包含稳定渲染更新/提交/GPU等待，不包括截图编码、资产首次加载或动力学。

|补充上侧薄边航线52点|47.44 / 52.84|23.77 / 33.22|

规范眼点云密度前后差为0。补充同航线613帧、30Hz仿真采样的连续图像，613帧满足历史使用条件，276帧眼点位于薄云；该连续片段仅更新后验收，不冒称更新前后连续视频对照，采集也不是实时录屏。视频：`build/cloud-edge-perf/cloud-edge-30hz.mp4`。

海面48帧亚像素移镜：白天孤立亮对比25,824→10,449/百万像素，暗对比7,623→4,498/百万像素。这是相邻像素对比指标，包含真实波光，不能当成坏点计数。原始未配准移镜亮度差并未全面改善：白天0.284→0.395，日落1.340→1.478（8bit）；日落暗对比也略增，仍有残留，不能声称已消除闪烁。夜间该指标0.097→0.091。
