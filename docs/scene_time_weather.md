# 场景时间与区域天气

原有三个软件、单云对象及占用/断裂/碰撞链路保持不变。天气定义在 `.vscene.json` 和检查点的 `weather` 中，由 `VoxelSceneSnapshot` 跨进程发布，避免各显控分别随机生成天气。没有 `weather` 的旧场景继续使用原气象参数。

## 使用

在原场景设计软件打开 `config/topics/taipei-weather.vtopic.json`，使用右侧「正式体素专题编辑 → 时间 / 天气 / 雨雪…」。可设置 UTC 零时刻、昼夜倍率、初始气象、天气转场和基础海况。对话框按当前仿真秒显示预览 UTC。保存专题或 `.vsimscene` 场景包，仿真主控重开后按同一时间线采样。编辑前需暂停。

示例专题仍为台北新数据联合场景，包含地形、原目标、单云和海洋。初始多云，120 秒开始用180秒转阴，360秒开始用120秒转雨，600秒开始用180秒转晴并保留潮湿外观。雪是单独可选的人工气象预设，不表示台北的实况。

```json
"utc_origin": {"year":2026,"month":9,"day":10,"hours_utc":4,"time_scale":1},
"weather": {
  "enabled":true,
  "initial":{"preset":"cloudy"},
  "transitions":[
    {"at_seconds":120,"duration_seconds":180,"state":{"preset":"rain","wind_speed_mps":7}}
  ]
}
```

UTC = 零时刻 + 权威仿真秒 × `time_scale`。昼夜倍率不改变物理固定步长和天气时间线；零倍率冻结天体时刻，仿真暂停同时冻结云、雨雪、波浪时间。统一日期换算支持跨日/月/年、闰日和向前回看。显示与装备环境计算使用同一日期函数。

## 天气字段

- 云与能见度使用 `clear` 晴、`fair_clouds` 晴天积云、`cloudy` 多云、`overcast` 阴、`storm_clouds` 厚乌云、`twilight_clouds` 晨昏云或 `fog` 雾。晨昏云预设安排较高的薄云和云隙，颜色由当前太阳高度和大气透射决定。
- 小、中、大雨使用 `light_rain`、`moderate_rain`、`heavy_rain`，雨强分别为 1.4、6、35 mm/h。小、中、大雪使用 `light_snow`、`moderate_snow`、`heavy_snow`，雪水当量分别为 0.55、2、6.5 mm/h。`rain` 和 `snow` 保留为中雨和中雪的兼容名称。各等级的能见度和积雪、湿润程度为仿真预设。
- 每个状态可覆盖预设中的字段。只有自定义字段的状态从晴天参数起算。

|字段|单位/意义|
|---|---|
|cloud_cover, overcast|0..1 云量、阴天天空和光照调制|
|cloud_base_m, cloud_top_m|椭球高，米，与既有地球云场一致|
|optical_depth|体积云光学厚度|
|visibility_m, fog_height_m|米，区域可见度与近地气象层尺度|
|wind_speed_mps, wind_azimuth_deg|米/秒、朝向角（北0、东90）|
|rain_mm_h|雨强，毫米/小时|
|snow_water_mm_h|雪水当量，毫米/小时，不是雪深增长速度|
|temperature_k, relative_humidity|气温、相对湿度；持久化的环境状态|
|surface_wetness, snow_cover|0..1 人工外观状态，不是积水/积雪质量守恒计算|

转场采用平滑曲线；能见度按消光量插值，风向取最短角度。时间线按仿真秒排序，最多256段，不接受重叠、非法数值、拼错的字段或不存在的预设。环境事务失败时不会部分修改日期或天气。

## 渲染和仿真边界

雨雪为原地球渲染器内的 GPU 实例粒子，不给每滴雨/每片雪创建 CPU 刚体。每类最多 9216 个近、远层候选粒子；强度筛选、随风斜落、雪花摆动、边界淡出、最小像素足迹和地形/目标深度遮挡在着色器中完成。相机附近的近层与远层用世界锚定的周期场绘制，边界渐隐，云底以上淡出，海面以下关闭降水。按天气曲线积分风位移，而不是直接用当前风速乘总时间。雨雪颜色随日照和曝光变化，夜间降低亮度。雨丝宽度和粒子密度是视觉采样参数，不能当作实测雨滴尺寸/浓度。

云量、云高、密度、光照、天空、雾、海面反射和能见度使用同一时刻的场景状态。地表湿润和坡向积雪是显示外观；不修改占用、碰撞形状、影像来源或传感器材料谱。温湿度为显式状态，尚未实现地表热平衡、融雪或结冰力学，不能据此声称红外积雪特征已标定。

海况可在编辑器中选用蒲福 0–8 级的风速与代表性风浪、涌浪参数。选择后用原有谐波模型更新水面、浮力和水下查询。能见度、云倒影、细波粗糙度和白浪随天气变化。基础波谱在编辑事务提交时重建，天气转场按风场连续更新细波和白浪。代表性海况属于人工设定，实际浪高也受风区、持续时间和水深影响。

装备环境服务读取相同 UTC、云量、能见度、云底和雨强。雨消光沿用原经验模型：归一化上限对应50 mm/h，当前常用预设在此范围内；雪使用所配能见度，不将雪水当量冒充雨滴消光。温湿度和积雪尚未进入经过标定的多光谱地表热平衡。不能把视觉雨雪粒子视为可逐滴测量的物理场。

## 验收

`voxel_scene_runtime` 检查连续转场、风向跨北、UTC 闰日/倍率、暂停单步、检查点/IPC持久化、非法编辑原子回滚，以及固定步长和体素拓扑不变。原有云/海GPU一致性与重投影测试继续运行。

地球测试程序实际 Vulkan 图像：

```sh
DISPLAY=:1 XAUTHORITY=/run/user/1000/gdm/Xauthority LP_NUM_THREADS=2 \
VSGRAYSIM_OCEAN_WEATHER_PASS=1 VSGRAYSIM_SCENE_WEATHER_PASS=1 \
build/gui/sim_earth_gui_tests --scene-ocean-capture build/scene-weather/native
```

设置 `VSGRAYSIM_WEATHER_EXPANDED=1` 增拍分级雨雪、晨昏与日月星空，以及同机位的蒲福 0、3、5、8 级海况。新增结果写入 `scene-weather.json` 的 `views`、`celestial`、`sea_wind`。

同一台北海岸、同机位，白天统一 UTC04:00 检查7种天气，并补日落、夜景、雨夜与黎明雪。每种白天天气另拍海岸与山地机位；中雨/雪对照关闭粒子图像，检查实际可见像素。关闭天气后检查云密度与雨雪复位。另各输出48张20 Hz仿真时间采样的带风雨雪原生帧，物理时钟仍冻结；这不是实时录屏。追加65帧晴→雨→雪曲线实际GPU更新验证，包括云形/光照缓存重建的渲染耗时，测试曲线特意压缩到8秒以覆盖连续转场，并非真实气象演变速度。

截图和编码不计入计时；报告的 `render_median_ms`/`render_p95_ms` 为稳定原生渲染/提交/GPU等待，不是完整动力学周期或GPU时间戳。本轮天气外观验收冻结物理时钟，不能用这些数值声称完整仿真实时。运行 `python3 tools/summarize_scene_weather.py` 检查原始截图、不透明覆盖、降水开关及风动画，并生成 `verified-summary.json`。

台北海岸数据仍有海域回退，验收报告保留 `source_coarse` 等来源标记，不因影像标称10米而改成全域高精度。海岸补充机位可见既有海陆拼接边界，本轮未宣称修复该边界。

## 2026-11-23 天气渲染优化

GPU 以每个云对象为单位缓存太阳或月亮、天顶、斜向天光三种光学深度。每个对象的网格为 24³，带保护边界的 RGBA16F atlas 占约 19.3 MiB。它读取现有的密度缓存。同一次 GPU 提交先更新密度，再更新光照，最后采样光照。读端以版本检查拒绝过期结果，静止天气可跳过重算。视线积分保留原来的局部密度和步距，近处用已采样的精细密度补偿光照，补偿随距离衰减。远景光照经过插值，外观存在近似误差。参数 `VSGRAYSIM_CLOUD_LIGHT_FIELD=0` 可诊断原光照路径。

缓慢的天气变化保留受限的重投影权重，较大跳变和不匹配的像素仍丢弃历史。雨滴和雪花各有落速分布，雪花摆动速度与幅度不同，降水变强时粒子逐步可见。地表的积雪权重加入低频斑驳、坡度和基于 RGB 的植被外观估计，湿润地面保留漫反射压暗及轻微斜视反光。雨雪、湿润和积雪仍属于显示参数。

地球程序使用同一台北海岸场景、相机和 UTC，分别跑 11 个定点天气、65 帧的 8 秒转场，以及军舰、地形和海洋的 120 次完整循环。每次完整循环推进两个 20 ms 固定物理步，再提交原生渲染并等待。记录物理、浮力、水动力和端到端墙钟耗时。完整循环覆盖场景、碰撞、水动力和显示，传感器测量链由单独回归覆盖。光照缓存会增加显存，并可能增加首次图形管线编译耗时。暖机、图像回读和 PNG 保存独立于报告的渲染计时。

## 2026-11-23 雨雪外观

近景和中景使用不同尺寸的世界坐标粒子场，覆盖横向 60 和 144 米。两层在边界处渐隐。雨丝的落速、长度和宽度各有变化。雪花会随风漂移、摆动和翻转，远处外形按像素足迹柔化。雨雪亮度随日月和雾变动。每种降水最多提交 9216 个候选实例，未启用的一种由实例区间跳过。

强降雨使云底与雾层的显示亮度降低。海面、地形与云消费同一种显示雾色调制。近海可见雨滴冲击形成的细小扩散纹，远处过渡到既有的反射粗糙度。积雪覆盖依据坡度、地表颜色和两个空间尺度的斑驳。涟漪属于材质法线变化，积雪属于材质覆盖。

台北地球窗口在同机位、同 UTC 对照前一版本。960×540 下，中雨、大雨、雪的稳定渲染中位分别为 18.97、18.17、20.35 ms，前一版本为 19.42、20.41、20.29 ms。65 帧压缩转场的渲染 P95 为 57.43 ms，前一版本为 59.42 ms。物理时间冻结。七项回归通过，其中包括雨纹随时间变化、在干燥或远距离足迹下消失的 GPU 检查。

## 实拍参考与台北重拍

积云检查云顶与云底的明暗、背光边缘和晨昏色差。渲染用现有光学深度计算散射与遮蔽，按云的位置修正晨昏太阳高度。低空暖色雾沿太阳方位增强，并随仰角减弱。同一日落时刻补拍迎光与背光视角。 [WMO 云图集实拍册](https://cloudatlas.wmo.int/docs/wmo_407_en-v2.pdf) · [WMO 积云的形态与受光](https://cloudatlas.wmo.int/en/explanatory-remarks-and-special-clouds-cumulus.html)

海面检查浪峰亮带是否随风拉开、太阳反光是否随波面起伏而破碎，以及岸边水下轮廓是否过于显眼。海面反射逐条处理跨越地平线的采样光线，白沫沿风向变形并随像素覆盖面积过滤。远处的水下背景用光学衰减近似处理，实测水深与光学系数仍缺失。 [NOAA 蒲福海况照片](https://www.weather.gov/media/marine/SeaState.pdf) · [NASA 海面太阳反光实拍](https://science.nasa.gov/blogs/earth-matters/2016/11/09/ground-to-space-a-glittering-path-of-san-francisco-sunglint/)

雨雪检查近处粒径、远近的能见度和浅雪下面的地表层次。雪斑按三个尺度混合，使用视空间光线估计像素覆盖范围，减轻地心坐标精度引起的近处细碎亮点，并让缓坡的覆盖连续变化。雨雪外观沿用原有粒子预算和场景时间，积雪仍是材质覆盖。 [USGS 洛矶山初雪实拍](https://www.usgs.gov/media/images/early-snowfall-rocky-mountain-national-park) · [美国国家气象局风雪能见度记录](https://www.weather.gov/fsd/20250319-HighWindandBlizzard)
