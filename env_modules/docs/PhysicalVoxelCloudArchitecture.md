# 物理体素云完整架构

## 1. 验收目标

目标不是用噪声雕刻一个云壳，而是让可见云、遮光、传感器衰减和外物扰动都来自同一份持久化凝结物体素状态。必须同时满足：

- 从轨道、高空、云顶、云内、云底和地面观察均无平面层、球形拼接或计算域边框；
- 云团随湿度、温度、压力、CAPE、风切变和太阳加热生成、成长、消散；
- 飞机、旋翼、发动机尾流能够交换动量、热量和水汽，并产生可持续演化的孔洞与尾迹；
- 可见光、红外、雷达和物理查询采样同一个版本的水凝物场；
- 1920×1080 RTX 目标为稳态 P95 小于 33 ms，重定位帧不破坏状态一致性。

## 2. 单一状态模型

每个活动体素至少保存：速度 `u/v/w`、位温、压力扰动、水汽 `qv`、云水 `qc`、雨水 `qr`、冰晶 `qi`、雪/霰 `qs/qg`、液滴数浓度 `Nc` 和亚网格湍动能 `TKE`。渲染密度只从 `qc/qi/qs` 推导，禁止在 fragment shader 中用噪声重新生成云形。

天气系统只输入边界条件和强迫项：三维温湿廓线、压力、风切变、地表热通量、CAPE/CIN、辐射加热与降水背景。没有真实天气数据时，可用确定性的相关扰动初始化这些气象量，但扰动本身不得直接作为渲染密度。

## 3. GPU 求解器

### 3.1 动力学

- 采用低马赫数 anelastic/Boussinesq 形式，MAC 交错网格存速度；
- 时间推进使用 CFL 自适应 RK2，标量采用守恒 MacCormack/BFECC，并做局部极值限制；
- 压力投影由当前 Jacobi 迭代升级为多重网格 V-cycle；
- LES 使用动态 Smagorinsky 或 WALE，涡量约束只补偿网格耗散，不能凭空生成水凝物；
- 开放边界注入真实环境廓线，顶部使用阻尼海绵层，避免当前 clamp 边界反射。

### 3.2 微物理

- P0：暖云双矩方案，包含凝结、蒸发、自转换、碰并、雨滴沉降与潜热；
- P1：加入冰晶、雪和霰，处理冻结、融化、凝华、Bergeron 过程；
- 有效半径和液滴数浓度进入 Mie 光学、雷达反射率和红外吸收，不能再使用固定 12 μm 半径。

## 4. 稀疏多分辨率体素

使用 GPU 驻留页表管理 `32³ + ghost` 砖块：

- L0：12 m，仅分配在云边界、高涡量、飞机和传感器近场；
- L1：24 m，当前局部主体求解层；
- L2：48–96 m，局部天气系统和远场动力层；
- 全球层：天气驱动的 0.5–10 km 水凝物砖，不再使用可见程序化云壳。

细化判据综合 `|∇qc|`、涡量、TKE、相变速率和与相机/交互体距离。父子级切换执行质量、总水和动量守恒限制；显示、物理与传感器只在仿真步边界切换同一个版本号。

## 5. 光学

- 根据 `qc/qi`、有效半径和波段查表得到消光、单次散射反照率与相函数；
- 太阳光采用体素深阴影缓存，局部变化砖增量更新；
- 主视线使用自适应步长、空砖跳跃、蓝噪声抖动和时间重投影；
- 多次散射使用能量守恒的扩散近似/低阶角向缓存，不用人为整体提白；
- 云底亮度必须由太阳路径、天空漫射和水凝物光学深度共同决定；
- 地形、海洋、云互相投影阴影，并共享太阳/月亮与曝光真值。

## 6. 外物交互

外物以时变 SDF 和面速度写入活动砖：排开凝结物，向空气交换动量，并注入发动机热量、水汽和颗粒物。旋翼采用桨盘动量源，固定翼采用尾涡线/面源。交互结束后孔洞、卷吸和尾迹必须继续由同一个求解器演化，而不是播放特效。

## 7. 分阶段落地

1. **正确性**：移除可见球形种子；气象场初始化；开放边界；质量/总水/散度自动测试。
2. **动力学**：BFECC/RK2 平流（已接入）、多重网格压力、LES 和自适应 CFL。
3. **微物理**：暖云双矩、沉降，再加入冰相和降水。
4. **稀疏化**：12/24/48 m 砖、后台准备、版本化发布与守恒 LOD。
5. **光学**：深阴影缓存、波段光学、时间重投影、空砖跳跃。
6. **闭环**：飞机/旋翼/尾流接入，并让显示、物理、光电、红外和雷达共同验收。

## 8. 自动验收

- 数值：每 10 分钟仿真总水误差小于 0.5%，压力投影后散度 L2 下降至少两个数量级；
- 视觉：六高度、昼夜、顺逆光、入云/出云基准图和时间稳定性 SSIM/闪烁指标；
- 交互：飞机穿云前后质量守恒、孔洞寿命、尾涡衰减曲线；
- 性能：稳态/重定位/快速穿云分别记录 GPU P50/P95/P99、显存、活动砖数和传感器延迟。


## 2026-11-17 实施边界与回归入口

已实现：独立压力历史、固定时间子步、独立暖雨沉降、共享 GPU 液态水光学资源、
可选传感器绑定。回归包含压力热启动/重置、1/8/16/32 碰撞预算、批量子步与逐步执行等价、
暂停/追赶/回退、雨水向下输运守恒，以及真实目标在共享云场中的辐亮度衰减。

```sh
cmake --build build --target sim_earth_environment_tests sim_gpu_runtime_tests sim_earth_gui_tests -j 4
ctest --test-dir build --output-on-failure -R 'earth_cloud_ocean_consistency|simulation_offscreen_gpu_runtime'
build/gui/sim_earth_gui_tests --cloud-descent-capture /tmp/cloud-acceptance earth_display
```

传感器接入必须在其拥有的设备上、编译场景前创建 `CloudSceneBinding`，坐标矩阵为传感器场景
局部米坐标到 ECEF 的刚体变换。宿主负责选择采集时刻的场版本并先完成云求解；同设备共享
纹理不等于自动解决时间历史。未提供绑定时继续使用旧场景路径。

仍需单独实现/验收：混合相与双矩微物理、长期守恒与投影残差、跨设备/采集历史快照、
场景深度截断与线性 HDR 合成、时间重投影，以及真实气象资料和全链路性能标定。
